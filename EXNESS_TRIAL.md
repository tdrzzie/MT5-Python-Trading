# Exness cent trial: MT5-Python-Trading

Reserved magic: **26111302**. Only `exness_trial.py` is the guarded trial entry point. Original entry points are not approved for this shared-account trial.

The shared package and tracker live in the sibling `Monn/exness_arena` directory. Clone these forks as sibling folders. The launcher sets the repo identity before importing trading modules. Runtime account pins, initial equity, risk budgets, journal and credentials are excluded from Git.

Status: closed-bar adapter implemented; must pass read-only preflight and shared safety tests before activation.

Guarded strategy adapters use the original strategy classes: Monn MACross (10/20 SMA, 100-SMA and candle filters), or MT5-Python-Trading CrossOverStrategy (20/50 SMA). Both use closed M15 bars on all broker-discovered cent currency, metal and crypto pairs. The inventory refreshes every minute. Disabled, close-only, non-pair contracts and conversion indicators are excluded from new entries; existing trial positions remain manageable. Missing history is reported per pair rather than stopping the whole scanner. Monn retains its configured 0.25% price stop; the crossover adapter adds a mandatory 2-ATR stop and 2R target because the original multi-symbol runner sends no stop. These adapters are distinct experiment configurations, not an unmodified upstream performance claim.

Current deployment: equal stop-risk caps of 3.50 USC per ready bot; reserve 10% for execution drift; one initial buy and one initial sell per pair per bot may coexist; further same-direction entries require every existing position in that direction to be individually profitable after swap and known opening fees; there is no numerical position-count cap; combined stop-risk cap 7.00 USC; per-bot cumulative loss budget 5.2444 USC; account-wide equity decline gate 1%; maximum 0.01 cent lots per order. The local settings file remains authoritative; changing the watchlist never resets these limits, the baseline, deal history or position ownership. Skip if minimum volume exceeds budget. No pending orders, stop removal, stop widening, or cross-bot position changes. No upward rounding or account switching. Missing account state, stale quotes/tracker, and unknown order results block new entries.

The account-wide gate includes external position P&L and is an entry halt, not a guaranteed loss ceiling or automatic liquidation. Stop gaps/slippage can exceed estimated risk. Existing positions are excluded from bot results. Equal risk caps do not guarantee equal exposure or trade counts. Sampled drawdown is measured every 10 seconds. No API costs are incurred by the two initial rule-based adapters.

From the workspace parent, use the isolated Python environment and the scripts in `Monn/exness_arena`. Dashboard: http://127.0.0.1:8765 . Run `python -m exness_arena.control pause` with `Monn` on PYTHONPATH to stop new entries and exit runners without closing positions. Tracker remains read-only and continues reporting. There is no automatic restart or automatic halt reset. Keep Windows and MT5 running.

Use `Monn/restart_exness_trial.ps1` to preflight the current watchlist, stop only verified trial processes, preserve existing positions, and restart with updated code. It refuses to override an existing pause. The tracker reports per-repo pair coverage and data availability.

A fresh qualifying M15 signal may open the first position in either direction independently, even with an existing opposite position. Subsequent entries in a direction require every current same-direction position to be individually positive after swap and known opening fees. The guard enforces this atomically before each submission. Zero, negative or non-finite net profit blocks additions. New opposite signals do not automatically close existing positions; server-side SL/TP remain active. Combined monetary risk and loss limits still apply. Neither a numerical position-count cap nor a lifetime entry-count cap applies.

Additional guarded profiles are available for Aurum EMA, original SuperTrend and original Sunrise (eight supplied pair profiles). All enabled repos share the same unchanged monetary limits. The launcher reads the local enabled list dynamically; adding a repo does not create a separate account-wide risk allowance.
